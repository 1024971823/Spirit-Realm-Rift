# 本地私有联机容量短测报告

日期：2026-11-21 UTC。本报告是同机 loopback 短测证据，不是近生产环境60分钟容量验收，也不是大陆三网验收。未打开公开入口。

## 环境与方法

- Intel Core Ultra 5 336H，12逻辑CPU，31,603 MiB RAM；同机运行PostgreSQL、Redis、服务端、加载器及其他开发测试进程，非独占云实例。
- Node v24.22.3原生TypeScript，无tsx；production私有LOCAL_HTTP模式；1网关+4独立游戏worker，每worker稳态25房。默认真实180秒局长，20Hz。
- 1000独立已登录账号，600活跃协议客户端，100满员房；五分片对照为60公开3v3+40邀请码房，含团队/核心/FFA，地图交替，无机器人。
- LOAD_DELAY_MS=60通过应用计时器在上下行各注入30ms；不是网络整形真实RTT，未模拟丢包、抖动、TLS和公网带宽。
- worker帧指标包含各IPC command的inputProcessingMs和本帧所有stepRoom；最多1200帧滚动样本。下表为日志最大已报告滚动P99，不是全程原始帧总体P99。
- CPU每约5秒按/proc采样，100%为一核；服务端占用合计网关+4worker，不含DB/Redis。RSS简单相加含共享页重复计数。资源采样在测量开始约20秒后启动。

## 跨局与结算

- 两次各跨过完整180秒首局；DB各观察到100场finished/600玩家结果，第二批100场active/600席。五分片首批09:22:02.499–09:22:04.246 UTC开局，第二批09:25:03.645–09:25:06.230开局。
- 五分片finished summary团队480席、核心60席、FFA60席；summary无mapId，地图混跑由加载器配置保证，不将SQL null mapId当作地图证据。
- 重复(match_id,player_id)组0；此检查不替代专门事务/重试故障测试。测后metrics的worker_failures_total=0、settlement_failures_total=0，网关日志无运行异常。

## 唯一错误及未完成验收

- shard3在180–190秒换局窗口通用errors从0变1，当时脚本没有输出具体来源，原计数保留，不能报告为零错误通过。
- 时序支持原局结束后重连等待7.5秒超时的解释：shard3于09:22:03.672开始测量；第180秒resumeIndex=90，选本片30号，即fixture630；其旧局e381d4de-f7b9-4e8b-aa8d-cce3e7133499在09:25:03.626提交finished，随后09:25:05.941入新局。09:29:17.906用该账号GET /api/matches/:id返回HTTP200、finished和完整100XP结算。旧日志未记录当时reconnect的matchId与错误类型，这仍是有时序/终态支持的解释，未直接归因。
- 尚未完成独占近生产实例60分钟持续压测、真实60ms网络RTT整形、大陆三网、HTTPS/WSS公网带宽评估；本地短测不能宣布1000人正式容量验收通过。
